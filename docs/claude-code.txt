Claude Code
===========

网页直接运行本机原版 claude CLI。不使用 Claude SDK，不直接调用模型 API。
运行时不读取 cc 脚本、cc.toml、cc 的偏好文件或公共设置源。
分类、与其他 harness 的边界及后续接入规则见 docs/harness.txt。

配置
----

默认：~/.coding-agent-web/claude-code.json
与 data.db 同目录。CODING_AGENT_WEB_DATA 改变数据库位置时，配置跟随数据库目录。
首次读取模型列表时自动生成，不覆盖已有文件。设置 > 模型 > Claude Code 显示路径，
提示编辑文件；保存后点刷新，关闭设置后输入框也会刷新列表。

默认文件提供一个“Local Claude Code”入口，沿用本机原生配置和登录：

  {
    "profiles": [
      {
        "id": "default",
        "name": "Local Claude Code",
        "provider": "local",
        "configDir": "~/.claude",
        "permissionMode": "manual"
      }
    ]
  }

增加独立模型，例如：

  {
    "profiles": [
      {
        "id": "example-my-model",
        "name": "Example My Model",
        "provider": "example",
        "model": "my-model",
        "configDir": "~/.claude-profiles/example-my-model",
        "env": {
          "ANTHROPIC_BASE_URL": "https://gateway.example/anthropic",
          "ANTHROPIC_AUTH_TOKEN": "env:MY_MODEL_TOKEN"
        },
        "effort": "high",
        "permissionMode": "manual"
      }
    ]
  }

id 是网页中稳定的 profile 标识，不是传给模型服务的 model。
model 才是 CLI 的 --model；不写时用原生默认模型。
name 只是界面标签，输入框那一行显示的永远是 name，不参与请求。
所以网关把模型改名后只改 name 不会生效，旧 id 照样发出去。

  { "name": "OpenCode · DeepSeek V4.1 Flash", "model": "deepseek-flash" }   <- 显示 V4.1，实际发 deepseek-flash

这类错误来自服务端，不是 harness：CLI 把 410 / 404 的原文当成一条回复输出，
界面上就是一条普通消息（例：410 Model deepseek-flash has been deprecated）。
遇到就核对一遍 model 和 env 里的 ANTHROPIC_*MODEL，两处都改了才会生效。

provider 用于菜单分组。id 必须唯一，每个 profile 必须使用独立的 configDir。
不写 configDir 时默认 ~/.claude-profiles/<规范化后的 id>。
enabled:false 隐藏该模型并停止发送，已有历史仍可查看，不会静默改用别的模型。

有 env 时，由这份配置管理模型环境，清除父进程继承的 ANTHROPIC_*。
model 对应的 Opus/Sonnet/Haiku 和 small-fast 映射自动补齐，env 中的显式值优先。
值支持字面字符串、env:NAME、$NAME；缺少环境变量会明确报错。
额外 headers、上下文窗口、compact 参数也放在 env 中。
不写 env 时沿用该 profile 的原生设置；env:{} 清除旧 endpoint/token，
model 指定的模型映射仍会补齐。因此 ~/.claude 不等于“官方 OAuth”：原生设置也可能有第三方路由。

permissionMode 支持 manual、acceptEdits、plan、bypassPermissions。
默认 manual。只有明确配置 bypassPermissions 才启用跳过权限检查。
effort 支持 low、medium、high、xhigh、max。

新建配置文件权限为 0600，不应提交到 Git。模型接口不会返回 env 或 token。
本机现有 10 项模型已一次性迁移到独立配置，并保留原 profile 目录；
之后修改 cc 的配置不会自动影响网页，反之亦然。代码中没有迁移脚本或回退读取逻辑。

目录与会话
----------

  网页选择项目和 profile
          |
          v
  claude CLI
    cwd                 开发目录
    CLAUDE_CONFIG_DIR   选中模型的原生配置目录
          |
          +-- 原生工具、MCP、skills、hooks、插件、子代理
          +-- 原生 projects/<项目>/<UUID>.jsonl
          |
          v
  stream-json -> 现有消息气泡、思考、工具卡、审批和问题表单

不改变系统 HOME。默认 ~/.claude 沿用 CLI 的特殊规则，元数据仍是 ~/.claude.json。
新 profile 按需创建，共享能力通过软链指向 ~/.claude，已有目录和文件不覆盖。
凭据、历史、项目记忆不会跨 profile 复制。它不是操作系统沙箱，项目文件仍是同一份。

索引 harness=claude-code；model 存 profile id；session_path 固定该 profile 根目录。
读取历史时在该 profile 的 projects 下按 UUID 定位，兼容原生目录命名和长路径。
索引不保存第二份聊天正文，也不会自动导入全部终端历史。
已索引的项目在网页重启后仍可续聊和浏览文件，不要求先创建 pi 会话。

已有对话的 harness 和模型/profile 都锁定。模型名仍显示，但变淡、不能打开菜单；
空闲和运行中一样。只有显式新建对话时可以选 profile，发送过程中也不能换。
要换模型先新建，不因选模型自动创建对话或复制草稿；原会话和草稿仍留在原位。
服务端固定 harness、provider、profile id、cwd 和 profile 根目录，原生 /model 指令也拒绝。
不要用已有 profile id 改绑另一模型或目录；增加新 profile id 和独立目录后再开对话。
/clear、/reset、/new、/resume、/fork 等会话内换 UUID 命令不透传，使用网页的显式新建。
若原生流程意外切换 UUID，停止该连接并提示，不把新上下文或任务写到旧索引下面。
终端和网页可以接力恢复同一个原生 UUID，但不要同时写同一条会话。

运行与交互
----------

每条活跃会话一个本机 CLI 进程，同一会话多轮复用；空闲回收后用 --resume <UUID>。
不用 --continue，不使用 --bare，不替换原生 system prompt，不关闭编码工具或会话持久化。
CLI 未安装或启动失败时，只报 Claude Code 的错误，不影响其他 harness。
PI_WEB_CLAUDE_BIN 可指定本机 claude 可执行文件，默认从 PATH 查找。

使用 --print、--input-format stream-json、--output-format stream-json、
--include-partial-messages、--forward-subagent-text，以及 CLI 原生 stdio host 控制消息。
没有安装或导入 SDK。控制协议集中在 harness/claude-code/runtime.ts。
开发验证版本为 Claude Code 2.1.310；旧版不识别参数时应先升级本机 CLI。

支持文本、图片、思考和工具参数流式显示、工具结果与 Edit diff、子代理进度、
权限批准/拒绝、AskUserQuestion 单选/多选/其他答案，以及 MCP 的 JSON 输入请求。
未知控制请求拒绝，不自动替用户作答。被原生策略拒绝的工具不会在网页端绕过。
MCP JSON 输入仍由原生 CLI/MCP 服务校验；特殊的原生终端对话框不伪装成已支持。

首次进入未信任项目时，由网页明确确认加载项目 hooks/MCP。
已有原生 trust 可以沿用；网页新确认保存在 data.db，不覆盖 CLI 正在维护的元数据。

输入框的停止按钮使用 CLI interrupt 停止当前回复，超时升级 SIGINT / SIGTERM / SIGKILL。
后台任务另有自己的停止按钮，见下一节；不能把主轮结束当成所有后台任务都已结束。
网页断开不终止正在进行的任务；重新打开读取原生历史、当前回复和待回答问题。
流式与完整消息按原生 id 对齐，不重复追加。侧栏可显示运行中和等待输入状态。
用量和费用取原生最新累计记录，不重复累加每轮快照；费用是 CLI 估算，不是代理账单。

运行中可以像 pi 一样继续输入：引导（Enter）立即打断当前轮并处理这条消息，
后续消息（Alt+Enter）排到当前轮结束后。两条都进入网页侧的待发队列，输入框上方
可按顺序显示并整体召回；停止按钮会同时清空待发队列。
引导通过 CLI interrupt 结束当前轮，队列中的消息在 result 之后按引导优先、后续次之
逐条写成下一轮；轮与轮之间不向浏览器发 agent_end，避免运行状态闪烁和误报完成。
分支编辑等 pi 专用控件仍不套用到 Claude Code。

标题操作优先取原生 custom-title / ai-title；headless 运行通常不写原生标题，
此时用该 profile 的模型跑一次临时 CLI（关闭工具和 MCP，低 effort）生成标题，
结束后删除临时原生会话，不改动当前对话和历史。

后台 shell、Monitor 与子智能体
-----------------------------

Claude 会话的输入框上方有「任务」入口。点开列出原生任务，点击一行查看详情。
只在 Claude 页面按需加载；状态、请求、页面兼容逻辑均在 harness/claude-code 内，
公共 ChatWindow 只登记和组合这个面板，不把原生任务分支加进公共会话 hook。

  shell      显示命令、状态、输出尾部；可停止，前台任务可转后台
  Monitor    显示原生监视任务、输出与结束状态；可单独停止
  子智能体   显示任务类型、进度、工具次数、耗时和父子关系；可查看思考、正文与工具卡
             前台任务可转后台，后台任务可单独停止

启动和继续工作仍交给原生 Agent/Bash/Monitor 等工具，不在网页里重写这些工具。
例如让 Claude 启动一个后台命令、监视日志、派一个子智能体检查代码，随后在任务入口
查看和控制它们。Web 不另外执行一条 shell、启动另一个 agent 循环或轮询模型 API。

查看输出、停止和转后台走原生控制请求，不额外发起模型轮次：
  get_task_output    shell/Monitor 的末尾最多 8 KiB，按纯文本渲染，不执行 HTML 或终端转义
  stop_task          指定当前会话的 task_id，结果等原生事件确认，不把按钮点击伪装成已完成
  background_tasks   按原生 tool_use_id 将前台 shell/子智能体转入后台，相当于终端 Ctrl+B

Monitor 本身按 CLI 规则工作，其事件可能触发新的模型回复和费用；读取面板不会。
Monitor 可能以 local_bash 类型上报，按原始 Monitor 工具归类，不能因此显示成普通 shell。
子智能体对话来自同一 profile、同一主会话下的 subagents/agent-<id>.jsonl，按原生提交
的消息块刷新，不宣称逐 token 转发。详情只展示末尾 120 条消息，省略时有提示。
不会把它改造成 pi 子代理会话，也不会在网页侧存第二份原生正文。

状态分别处理 task_started、task_updated、task_progress、task_notification，
background_tasks_changed 是完整集合，收到时替换，不靠「开始减结束」猜测。
终止补丁 killed 也会结束任务，不要求一定收到 stopped 通知；run_id 防止旧轮次回写。
主回复与后台工作分别计状态，后台运行不让输入框误以为还在流式回复。
只在 CLI 明确标记 ambient 时把任务排除在会话活动指示之外，不按 Monitor 名称猜测；
仍有原生后台任务或待回答审批时保留进程，避免空闲回收杀掉工作。

CLI 提供 agent_id 时，子智能体的审批/问题会标出所属任务；主轮结束不清掉后台审批，
等原生取消或进程退出关闭。
初始化声明 perTaskStopAffordance，让原生 interrupt 保留可以单独停止的后台子智能体；
强制结束进程或服务退出仍会影响其中的所有任务，不能承诺它们跨服务重启继续运行。

面板只控制已索引会话自身的任务，不接受浏览器传来的 profile、日志路径或输出文件路径。
任务操作携带展示时的 run_id，已恢复到新轮次的旧按钮会被拒绝；禁用 profile 后仍能查看
历史并停止已经运行的进程。浏览器隐藏时暂停轮询，返回时恢复；收起面板停止读取详情。

CLI 离线时，从原生日志恢复任务摘要和子智能体对话；不能确认的运行状态写「状态未知」，
不自动重跑 shell/Monitor。离线时不读取实时 shell 输出，也不盲读通知里的 output_file。
原生日志、输出或当前 CLI 不支持对应控制时明确报错，不伪造空输出或完成状态。

适配范围
--------

  已接入    文本/图片、思考与工具流、Edit diff、原生审批、AskUserQuestion、MCP JSON 输入，
            shell/Monitor/子智能体任务查看、转后台/停止、原生历史和切页重连
  原生可用  原生 tools/skills/MCP/hooks/Agent 定义仍由本机 CLI 加载，不代表都有独立设置页
  尚未专门适配  Agent 定义编辑、团队成员发消息界面、定时任务管理、云会话/Remote Control、
                claude --bg 常驻会话管理、会话内换 UUID 的流程，以及特殊原生终端对话框

后台 Bash/Monitor/子智能体任务不是 claude --bg 创建的另一条常驻会话。
这里不扫描或导入全部终端后台会话，不把未接的功能伪装成完整 CLI 界面。
新增能力继续在本 harness 内接，按上表更新支持范围。

验证
----

  node_modules/.bin/tsc --noEmit
  npm run lint
  npm test

真实 CLI 的隔离协议测试：

  CLAUDE_CODE_TEST_BIN="$(command -v claude)" \
    node --experimental-strip-types --test harness/claude-code/*.test.mjs

测试使用临时 HOME、临时 profile 和本地假网关，无真实模型请求。
覆盖原生 Bash/Read/Edit、审批、提问、连续两轮、重启恢复、中断后续聊、引导打断与
后续排队、召回/停止清空队列、临时会话标题生成与清理，
以及配置生成、模型隔离、历史归并、索引保护、/model 拦截和缺失 CLI。
网页组件、hook 与接口另有模型锁定、不自动新建、发送、切页、原生端点、问题回传和重连历史检查。
任务检查还覆盖原生前台转后台、Monitor 输出、子智能体对话/子任务、逐任务停止、主轮中断
保留后台 agent、进程退出后恢复历史、集合替换、终止补丁、旧 run 丢弃和 profile 路径约束。
client 检查覆盖切会话/切 run 的迟到响应、隐藏页恢复、操作不伪造状态和错误后的手动重试。
隔离浏览器组件检查不等于运行中 Web 服务已更新；构建与重启仍由用户执行。
