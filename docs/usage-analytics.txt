用量分析

入口：设置 > 用量分析。不需要打开项目。

采集
- 服务运行期间每小时自动采集。启动时检查，超过一小时未采集则补采。
- 点击“立即采集”可重新计算。页面读取数据库，不在每次打开时扫描 session。
- 按服务所在机器的本地时区划分日期。跨天会话按每条记录的时间归属日期。
- 默认扫描本机各 harness 的会话目录及配置的 profile，不限于 Web 内打开的会话。
- 服务停止时不会采集；再次启动会从仍存在的历史文件补算。

存储
现有 ~/.coding-agent-web/data.db；CODING_AGENT_WEB_DATA 可覆盖路径。

session 文件 -> 分 harness 解析 -> 日汇总与小时明细 -> SQLite -> 仪表板

usage_days        每天一条总量
usage_buckets     日期 + 小时 + harness + model + provider 的汇总
usage_collection  最后成功采集时间、来源诊断、错误

usage_buckets 的 hour=-1 是独立的每日维度汇总；0..23 是小时汇总。
查询总量不能把这两类相加。会话数按 sessionIds 去重，不能直接累加。

例子：10 月 26 日上午采集 100 万 tokens，下午重算为 150 万。
数据库保留 150 万，不是 250 万；10 月 27 日另存新记录。
重新采集会覆盖本次扫描包含的日期。源文件已删除的历史日期保留旧快照，
因此清理日志不会清空所有历史；不能从已删除的源文件重建明细。
写入使用事务；来源不可读或采集失败时保留上次成功数据。

口径
- 输入、输出、缓存读取、缓存写入分别存储；总 tokens 遵循各 harness 的记录口径。
- 费用只使用日志中明确记录的金额，不用模型价格表反推；未知费用不是零。
- Grok 的聊天文件不含完整用量，需读取独立 usage.json 的逐轮明细。
- dsh 多版本 session 只读取最新版本；不把累计计数重复累加。
- 模型或 provider 不存在时保留未知，不根据当前设置猜测历史归属。
- 没有记录的指标无法还原。来源诊断显示解析缺失、重复记录和采集限制。
- 数据库只保存聚合指标和去重所需的会话标识，不保存聊天正文或 API key。

接口
GET  /api/usage  读取已存快照与采集状态
POST /api/usage  立即采集并返回快照；并发请求复用同一进程中的采集任务
