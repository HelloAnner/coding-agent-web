新增 harness 接入自检清单
========================

用途：接入评审、实现自测与发布验收。各家定位与能力现状见 docs/harness.txt。
这里列验收要求，不代表当前每个 harness 都已支持。每项填写：通过 / 失败 /
不适用，并附测试名或复现证据。不适用须说明原因，UI/API 不能宣称支持。
身份、生命周期、安全项失败不得算接入完成。证据记录原生版本，不保存凭据或私有正文。

一、边界与能力
--------------

[ ] 记录原生二进制/SDK 版本、协议、进程寿命、模型来源、配置与历史位置。
    先验证原生端两轮对话、恢复和中断；接通模型 API 不算接入 agent。
[ ] 分别标明支持、未接入、原生不支持：文本、图片、思考、工具、审批、提问、
    后台任务、统计、切模、原生命令、MCP、skills、扩展、队列和分支。
[ ] 配置列表、运行时挂载列表、实际可用模型分别验证。缺失、禁用、认证失败明确报错，
    不偷偷回退。切模追到执行参数/配置请求，不能只改菜单标签和索引。
[ ] 后端、事件、历史、浏览器 API、专属控件和测试归本 harness；公共页面只组合，
    路由只校验分流，不把私有协议塞进公共 hook。不照搬其他 harness 的能力。
[ ] 非 pi 不创建 Pi AgentSession、不写 pi 日志；浏览器不导入 fs/spawn/凭据入口。

二、身份与路由
--------------

[ ] 写出映射及不可变字段，例如：
      webId=dsh-example -> nativeId=<ACP id>
      harness=dsh, cwd=/work/repo, provider=<p>, model=<m>
      session_path=<原生日志目录>
    profile 型另记稳定 profile id、实际 CLI model 和 configDir。
[ ] 显示名、菜单值、原生 model、profile、网页 id、原生 id 不混用。
    重启后能从持久化路径恢复映射，不仅依靠内存 Map。
[ ] 发送、停止、SSE、状态、历史、审批、任务按索引 harness 分流，
    不继承新建框上次选择。共享内核按 nativeId 精确分发事件。
[ ] 已有会话锁 harness；profile 型锁身份。前端和服务端都检查，
    URL/body、/model 等原生命令不能绕过。配置编辑不能把旧 profile 改绑另一身份。
[ ] 同项目两条本 harness 会话，再与其他 harness 并行：模型、正文、工具、
    权限、cwd 和停止互不污染。覆盖 LAN HTTP 下的会话 id 生成。

三、运行状态：首屏和权威轮询都必须接通
--------------------------------------

[ ] 定义 starting、running、awaiting-input、stopping、idle、failed 的语义。
    进程存活不等于正在回答；主回复、后台任务和审批分别计状态。
[ ] 运行时枚举返回网页 id，不是 nativeId、PID 或所有常驻会话。
    初始化和停止等待期间也有 busy 语义，不能留下重复发送空窗。
[ ] 验证侧栏实际使用的首屏接口 /api/catalog/sessions，以及适用的 /api/sessions。
    runningSessionIds 命中索引行；审批状态同样接入。
[ ] 单独验证 /api/agent/running。它是周期轮询的权威快照；
    只改首屏、只加 runtime 函数、或发送后乐观点亮都不算完成。
[ ] 长任务切页返回、刷新、第二标签页，至少观察三个轮询周期：
    左侧转圈、停止按钮、输入锁一致；下一次轮询不误清真实忙态。
[ ] 正常、取消、失败、崩溃后状态收口。旧响应不能覆盖新状态，
    轮询失败不能假装全部空闲，前端猜测不能永久掩盖服务端漏报。

本次 dsh 回归案例：运行时知道会话正在运行，但首屏和权威轮询都漏了 dsh。
修复需同时聚合两个接口，并确认返回 webId；仅修改转圈组件无效。

四、启动、中断与结算
--------------------

验收生命周期（不要求实现采用相同状态名）：

  idle -> starting[先占锁] -> running -> settling -> idle
             |                 |
             |                 +-> stopping -> 等原生结算 -> idle
             +-> 启动失败 -> 清理/释放锁 -> failed
  running --内核退出--> 清理订阅/待处理请求 -> failed
  idle/failed --下一轮--> 按原生身份 resume，不隐式新建

  stop 已发送 != 原生已停
  主轮结束 != 所有后台任务结束
  浏览器离开只断订阅 != 停止 agent

[ ] 在任何 await（ready、initialize、new/resume、设模型）前占启动锁。
    慢启动下双击、双标签发送，只建立一次原生会话和本轮；其余返回 busy 或排队。
[ ] 共享内核单次初始化；重启会通知其他未结算会话。
    旧进程/旧轮次迟到事件不能清掉新一轮状态，使用代际或等效隔离。
[ ] 缺二进制、握手失败、超时、设模型失败释放锁，清理 pending、订阅和计时器，
    后续可重试。区分 ready、会话创建、prompt accepted 各自的成功边界。
[ ] 确认中断是通知、请求、控制帧还是信号。以原生 prompt 完成、settled 或
    逐轮 CLI close 结算，不要求常驻内核退出；HTTP 200 不是结算证据。
[ ] A 停止后立即发 B：B 必须拒绝或等 A 结算，不能抢跑；A 的迟到事件不污染 B。
    启动期间停止不能继续偷偷提交 prompt；重复停止幂等，空闲停止不启动进程。
[ ] 中断超时有明确升级和失败路径。正常、取消、崩溃、解析失败各只发一次终态，
    aborted/error 语义正确，停止后下一轮重置取消标记。
[ ] 后台 shell/子代理分别测试单独停止与主回复停止；不支持就说明。
    主轮结束不能清掉后台尚待回复的审批。

五、恢复、原生历史与 catalog
----------------------------

[ ] 首轮写唯一标记 harness-check-42，完成后由用户重启服务，再追问标记。
    用原生 resume 参数、同一日志、连续上下文共同证明恢复，不只看旧消息能显示。
[ ] 覆盖刷新、空闲回收、内核崩溃、服务重启、配置变化重启。
    保持 nativeId/cwd/profile；不承诺自动接回旧进程的后台任务。
[ ] 核对 new 和 resume 的真实响应结构，不假设它们都返回 sessionId。
    dsh 的 resume 只返回配置，应保留请求里已知的原生 id，后续 prompt/cancel 使用它。
[ ] 日志缺失、损坏、profile 禁用、版本不兼容明确报错；能读则保留历史查看。
    resume 失败不能自动 new，不能以空会话覆盖原路径。
[ ] 历史由原生写，网页只读。验证分支、compaction、工具结果、附件、压缩多帧，
    不盲拼全文件文本，不另存一份 pi 格式正文。
[ ] 成功创建后存 webId、harness、项目、provider/model/profile、session_path。
    创建失败无假行；原生已创建但索引失败可诊断，重试不重复建立上下文。
[ ] 只列已索引会话，临时模型探测会话不进侧栏；删除索引不删原生日志。
    重启后项目文件授权仍正确，不因内存授权丢失而误拒绝或越权。

六、协议、错误与 SSE
--------------------

[ ] 覆盖半行、分包、多帧、stderr 噪声、非法 JSON、未知事件、乱序响应和进程关闭。
    关键错误不吞掉，pending 不永久悬挂，stdout 按原生协议解析。
[ ] RPC 的 code、message、data 按实际价值保留/展示，先脱敏。
    data 测字符串、对象、缺省、含 token；不能只显示 Invalid params/[object Object]。
    例：message="Invalid params", data="session is not resumable"，界面能看到具体原因。
[ ] 认证失败、prompt 拒绝、工具失败、取消分别验收 HTTP、可见错误和终态。
    工具失败不等于会话消失，取消不能伪装成正常完成。
[ ] message/tool/request/run 用稳定身份，增量、最终消息、历史、快照按身份归并。
    例：partial="你"，final="你好"，最终只显示“你好”，不是“你你好”。
[ ] SSE 首次连接、断网重连、切页重订阅不重发用户 prompt；快照与订阅窗口不丢事件。
    重放/实时重叠时正文、工具、审批、统计、通知、音效都不重复。
[ ] 正文后终态前断网，终态后重连：能收口，不永久转圈、不重复完成通知。
    重放缓存超限有历史/快照兜底或明确限制。
[ ] 慢客户端、关标签、反复重连清理监听和计时器；一个 SSE 写入失败不影响 agent
    或其他订阅者；断开浏览器不擅自中止运行。

七、权限、安全与配置隔离
------------------------

[ ] 写明真实默认权限与可选模式，不照搬宽松默认。bypass 必须显式选择；
    trust、工具审批、问题、MCP 输入分别处理，不支持就隐藏/拒绝，不偷偷代答。
[ ] 批准一次、拒绝、取消、关闭弹窗、重复/过期回复、断线恢复各测一次。
    按原生 request id 回传；取消/断线不能自动批准。
[ ] API 校验会话归属、cwd、配置与日志根目录；覆盖 ../、编码、符号链接越界、
    跨 profile 路径、伪造会话/任务 id。恢复不绕过授权，新端点沿用认证规则。
[ ] CLI 使用 argv，不拼 shell；cwd、模型、文本中的引号/换行不能注入命令。
    子进程 HOME/代理/env 只影响本次运行，不修改全局环境污染其他 harness。
[ ] 双 profile 并行验证模型、凭据、历史不串用。逻辑隔离不宣称 OS 沙箱。
[ ] 用唯一假 secret 检查 API、SSE、错误、bundle、demo、Git 均无泄露。
    敏感配置限制文件权限，不覆盖用户原生配置。
[ ] 说明配置是立即、下一轮、重启生效还是旧会话禁止更改；缓存与执行端一致。

八、前端与 demo
----------------

[ ] 新建、已有、starting、running、stopping、失败态逐一检查控件。
    不支持不显示，暂不可用则锁定；不能点了无效、隐式新建或丢草稿。
[ ] 用真实事件验收正文、思考、工具、审批、问题、图片、错误、取消。
    统计缺失不编造，累计快照不重复累加。
[ ] 桌面、移动端、LAN HTTP、多标签、切会话验证发送、停止、历史与草稿。
[ ] 改共享 UI/接口时检查 demo 生成脚本、类型、mock、事件与捕获数据。
    demo 遵循控件契约或明确不可用；不涉及则说明原因，mock 成功不代表真机验证。

九、最小验收矩阵与交付
----------------------

以下是预期，不是实测结果；实际栏填结果及测试名/证据。

  场景              操作/故障注入              预期                         实际
  两轮对话          写标记后追问               原生 id 不变，上下文连续     待填
  首屏与轮询        长任务、切页等三个周期     两接口报 webId，不误清忙态   待填
  启动竞争          延迟 ready，双标签发送     一次 new/resume，其余 busy   待填
  停止后立即续聊    延迟 A 结算，立即发 B      B 不抢跑，A 事件不串入       待填
  重启恢复          用户重启后追问标记         原生 resume，不建空上下文    待填
  详细错误          注入 message+data          显示脱敏原因，释放锁         待填
  SSE 重放          partial/final 间断网       正文、工具、通知各一份       待填
  共享内核崩溃      两会话运行时模拟退出       均结算，下轮按原 id 恢复     待填
  权限与身份        取消审批、伪造路径/profile 不批准、不改绑、不越界       待填
  能力缺失          文本模型传图片、禁用模型   明确拒绝，不偷换模型         待填

[ ] 单测覆盖协议错误、消息归并、原生历史、路径；假进程/运行时测试覆盖启动锁、
    取消结算、崩溃、代际和恢复；路由同时测首屏列表与权威轮询。
[ ] 真实原生 CLI/SDK + 浏览器完成最小闭环，记录版本、模型、部署方式和未验证边界。
    假进程测试不等于真实 provider、权限模式、插件已通过。

    失败区分环境、既有问题、新增回归；未执行如实记录。
[ ] 不执行 next build 或 make start/restart/stop；服务重启由用户操作。
[ ] 更新 harness.txt 的能力现状与缺口。交付列已过、未过、不适用和证据；
    registry 已登记、菜单能选、demo 可演示都不能代替验收完成。
