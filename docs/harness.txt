多个 harness
==============

网页只做索引和同一套界面。真正的模型配置、凭据、会话文件留在各自 harness 的目录里。

```
设置 › 模型
  [ pi ] [ dsh ] [ grok ]
        |
        +-- pi    读写 ~/.pi/agent/models.json 和 settings.json
        +-- dsh   读写 ~/bin/ds/ds.toml（可用 DSH_DS_TOML 改）
                  会话文件在 ~/.dsh/sessions（可用 DSH_HOME 改）
        +-- grok  只读官方模型。不写自定义模型
                  列表在 ~/.grok/models_cache.json（可用 GROK_HOME 改）
                  会话文件在 ~/.grok/sessions/<编码后的目录>/<id>/

左侧会话列表
  不扫描 ~/.pi/agent/sessions，也不扫描 grok 或 dsh 的会话目录
  只显示 ~/.coding-agent-web/data.db 里的行
  刚装好是空的。新建一条对话才写一行
  不是 pi 的行，标题后面用分支名那一格的样式写上 harness。时间那一列不动
  pi 的行不写

输入框
  模型名右边是工具栏按钮，和模型选择同一套：高 32、无边框、圆角 9、点开向上的菜单
  菜单行只有 harness 的名字。换 harness 后，左边的模型列表跟着换
  会话一旦跑起来就不能换 harness。按钮还在，变淡，点不开
  模型可以换，还是这个 harness 自己的模型。正在回复时也能换，下一问才用新的
  打开已有对话时，输入栏用这场对话自己的 harness，不用新建框上一次选的
  pi 的会话文件决定它是 pi。模型以文件里正在用的为准，索引里不一样就改过来
  pi 的发送仍走 pi 自己的会话
  选了 dsh 或 grok，不会创建 pi 会话，也不会把模型 id 交给 pi
  dsh 的模型来自 ds.toml。选中后记在索引里
  grok 的模型来自官方列表。默认模型排在第一个
  grok 能发消息：每问一个 grok 进程，回复走这条会话自己的事件流
  dsh 真正发消息还没接上。这时发送会停住，草稿还在
```

grok 怎么跑
------------

不用 ACP，也不常驻。每一问 spawn 一个进程，会话文件归 grok 自己管。

```
grok -p "<prompt>" --output-format streaming-json \
     --permission-mode bypassPermissions \
     --model <model> \
     -s <新 uuid>        # 新会话。-r <uuid> 是续聊

stdout 是 NDJSON，一行一个事件
  text               -> message_update text_delta
  thought            -> message_update thinking_delta
  tool_call          -> toolcall_start/end + tool_execution_start
  tool_call_update   -> tool_execution_update / tool_execution_end + toolResult 消息
  end                -> agent_end + agent_settled

中断：给子进程 SIGINT（就是 grok 自己的 stop），3 秒不退再 SIGTERM
```

网页的 session id 就是 grok 的 session id（`-s` 自己指定，必须是 UUID）。
会话文件：`~/.grok/sessions/<url 编码的目录>/<id>/chat_history.jsonl`。

```
浏览器                useAgentSession 里按 harness 分叉
                       /                    \
                 harness=pi            harness=grok
            lib/rpc-manager.ts     harness/grok/runtime.ts
            /api/agent/[id]        /api/grok/[id]        POST prompt | abort
                                   /api/grok/[id]/events SSE
                                           |
                              chat_history.jsonl（grok 自己写）
```

事件名和 pi 的那套一样，所以聊天气泡、工具卡、停止按钮都不为新 harness 写第二套。

开关（都可选）：

```
PI_WEB_GROK_BIN               默认 ~/.local/bin/grok，再退 ~/.grok/bin/grok
PI_WEB_GROK_PERMISSION_MODE   默认 bypassPermissions（全放开）
GROK_DEFAULT_MODEL            没选模型时用，默认 grok-4.7
```

grok 自己的 `~/.grok/config.toml` 里 `[ui] permission_mode = "always-approve"`、`yolo = true` 也改成全放开了。

还没做的：图片附件、grok 的斜杠命令、思考档位（`--reasoning-effort`）、用量/成本统计。

索引
----

文件：~/.coding-agent-web/data.db（sqlite）

```
directories
  id, path, name

sessions
  id            这条对话在网页里的 id。pi 的用 pi 自己的 session id
  directory_id
  harness       pi | dsh | grok | ...
  provider
  model
  title
  session_path  harness 自己的会话文件。网页不搬这份文件
```

例子：同一个项目目录下两条对话。

```
path  /Users/anner/coding-agent-web
  hello   harness=pi    model=deepseek/deepseek-v4-flash
          session_path=~/.pi/agent/sessions/.../xxxx.jsonl
  hello   harness=grok  model=grok/grok-4.7
          session_path=~/.grok/sessions/%2FUsers%2Fanner%2Fcoding-agent-web/<id>
```

从列表里删掉一条，只删索引里的行，不删 harness 的会话文件。

代码放哪
--------

```
harness/types.ts              名字、配置目录、自己的 readModels / writeModel
harness/registry.ts           现在有哪些。路由只问 registry，不认识某个格式
harness/pi/                   pi。配置仍是 ~/.pi/agent。模型走原来的 /api/models
harness/dsh/                  dsh。读 ds.toml 的 [provider.*] 和 [model.*]
harness/grok/index.ts         grok 的目录、可执行文件、权限模式。只读官方模型列表
harness/grok/runtime.ts       每问一个 grok 进程，事件分发给订阅者
harness/grok/events.ts        NDJSON -> 网页已有的事件名
harness/grok/transcript.ts    chat_history.jsonl -> 聊天里的消息
lib/grok-client.ts            浏览器这边调 /api/grok 的几个函数
app/api/grok/[id]/            prompt | abort | 读transcript
app/api/grok/[id]/events/     SSE
components/harness/panels.tsx 设置页登记。每个面板只请求自己的接口
lib/catalog-db.ts             data.db。一条会话不能改成另一个 harness
```

隔离
----

```
pi 的代码不读 dsh 或 grok 的文件
dsh 的代码不读 grok 的缓存
路由和设置外壳不写某个 harness 的格式
一条索引行的 harness 不能改成另一个
pi 创建出来的会话文件，索引里也写成 pi
grok 不经过 lib/rpc-manager.ts，也不碰 pi 的会话文件
```

再加一个 harness：新建 harness/<名字>/，在 registry.ts 登记，自己实现 readModels。设置页再在 panels.tsx 登记。不要改 pi 的会话格式去凑它，也不要在路由里加一个 if。

ds.toml 和 grok 的 models_cache.json 里的 key 只留在那些文件里。接口不返回 key。
