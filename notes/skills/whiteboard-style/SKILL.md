# 白板风格

一句话：**图要论证，不要陈列。**

图不是排版过的文字。它用结构说明关系、因果和流向，是文字替代不了的。形状本身要携带含义。

## 两条检验

- **同构检验**：把字全删掉，光看结构还能读出概念吗？读不出就重画，不是加字。
- **教学检验**：别人能从这张图里学到具体的东西吗，还是只看到一堆带标签的框？好的图会展示真实格式、真实事件名、真实例子。

## 先判深度

| 概念图 | 技术图 |
| --- | --- |
| 讲一个思路、取舍、边界 | 讲一个真实系统怎么跑 |
| 抽象形状，3~6 个节点 | 5~8 个节点，真实名字 |
| 旁注写「为什么」 | 旁注写约束、坑、真格式 |
| 讲 30 秒 | 讲 2~3 分钟，带证据 |

判成技术图，就必须带**证据块**：真实代码片段、真实 JSON / 字段、真实事件名或调用链。不是「Protocol → Frontend」这种占位词。

## 研究前置（技术图强制）

画之前先查清楚真实入口、协议、事件名、数据结构、关键调用。查不到就用占位词说明「未知」，不要编。

- 差：`Protocol` → `Frontend`
- 好：`AG-UI 推 RUN_STARTED / STATE_DELTA` → `createA2UIMessageRenderer() 渲染`

## 多缩放

完整的技术图同时有三个层次：

1. **摘要流**：一条主线，一眼看完全流程（放在最上或最下）。
2. **分区**：带标签的区域，把相关的东西圈在一起（按职责、按阶段、按团队）。
3. **区内细节**：证据块、真实数据、具体例子。教学价值都在这一层。

## 容器纪律

**默认裸文字。** 每加一个框先问一遍：这句话去掉框还能读吗？能就删框。

| 用容器 | 用裸文字 |
| --- | --- |
| 它是这一段的焦点 | 它是标签、说明、元信息 |
| 需要和别的元素分成一组 | 它描述旁边的东西 |
| 箭头必须接在它上面 | 靠字号就能分出层级 |
| 形状本身有含义（菱形=判断） | 它是段落标题、副标题、旁注 |

层级用字号和颜色做，不要用框。28px 的标题不需要外面再套一个矩形。

硬指标：**装进容器里的 text 不超过 30%**。超过就是在画表格。

## 设计流程（写元素之前走完）

1. **判深度**：概念图还是技术图。
2. **理解**：每个概念问「它做什么」，不是「它是什么」；有什么转换和流向；别人要**看见**什么才懂。
3. **配模式**：给每个概念挑一个镜像它行为的视觉模式（见下表）。
4. **保多样性**：多概念的图，每个主要概念用不同模式。禁止一排等大方框。
5. **勾视线**：先在脑子里走一遍眼睛怎么走，要有清楚的视觉故事。
6. **再落元素**：这时才调 `notes_board`。

## 视觉模式库

| 概念在做什么 | 模式 | 怎么画 |
| --- | --- | --- |
| 一个分出多条 | 扇出 | 中心一个节点，多条 arrow 放射 |
| 多条汇成一个 | 收敛 | 多条 arrow 汇到一点 |
| 有层级、嵌套 | 树 | line 做树干分支 + 裸文字，不用框 |
| 有先后顺序 | 时间轴 | 一条线 + 10~20px 小圆点 + 旁边裸文字 |
| 会循环、会迭代 | 回环 | 箭头回到起点 |
| 模糊的状态、上下文 | 云 | 两个椭圆叠一点 |
| 输入→处理→输出 | 流水线 | 前 → 中框 → 后，前后差别要画出来 |
| 两件事对比 | 左右并排 | 两套结构平行摆，中间留白 |
| 分阶段 | 断口 | 用留白或虚线把阶段隔开 |

**线也是结构**：时间轴、树、分隔、主干，都用 `line` + 裸文字，比一排框干净得多。

## 形状的语义（不要混用）

| 它是什么 | 形状 |
| --- | --- |
| 标签、说明、细节 | 无（裸文字） |
| 段落标题、旁注 | 无（裸文字） |
| 时间轴上的点、连接点 | 10~20px 小 ellipse |
| 起点、输入、触发 | ellipse |
| 终点、输出、结果 | ellipse |
| 判断、条件 | diamond |
| 处理、动作、步骤 | rectangle |
| 抽象状态、上下文 | 两个重叠 ellipse |
| 层级节点 | line + 文字，不套框 |

## 颜色 = 语义

颜色编码信息，不是装饰。所有颜色取自 `references/color-palette.md`（唯一事实源），常用子集：

| 语义 | fill | stroke |
| --- | --- | --- |
| 主体 / 中性 | `#e8ecf7` | `#263d8f` |
| 辅助 / 旁支 | `#e8f1ee` | `#3f6b5b` |
| 起点 / 触发 | `#f7eadc` | `#a56536` |
| 终点 / 成功 | `#e2f1e8` | `#2f7a5a` |
| 决策 / 条件 | `#f3ead4` | `#9a6b2f` |
| 告警 / 回滚 | `#f5e4df` | `#a64b3c` |
| AI / 模型 | `#ece8f5` | `#66538f` |
| 失效 / 停用 | `#efeee9` | `#8c887d`（虚线） |
| 错误 | `#f2d8d2` | `#9c382c` |

- 裸文字的层级也用颜色：标题 `#263d8f`、小节 `#53679a`、说明 `#6f716b`。
- 一块板只用 **2~4 种语义色**；同一类东西全图同色，换色必须换语义。
- **深色描边配浅色填充**，不要浅描边配浅填充。
- 不要自创颜色。语义对不上就用「主体 / 中性」。

## 布局

| 尺度 | 尺寸 |
| --- | --- |
| Hero（最重要的那个） | 300×150，周围留 200px 以上空白 |
| Primary | 180×90 |
| Secondary | 120×60 |
| Small | 60×40 |

- **留白即权重**：最重要的东西周围空得最多。
- 流向：序列左→右或上→下，中心辐射用四面。
- **位置不代表关系**：A 和 B 有关系就必须有 arrow，挨着不算。
- 箭头走边界到边界，不要穿过元素；横平竖直，倾斜 ≤15°。

## 排版

- `fontSize 16`，`fontFamily 3`（等宽），居中；标题 20~28，旁注 13~14。
- `roughness 0`（干净、专业）；只有明确的「手绘头脑风暴」才用 1。
- `strokeWidth` 1 细线、2 常规、3 强调（只给主链路）。
- `opacity 100`，永远不要用透明度做层级。
- 一条 text 最多两行；成段文字属于笔记，不属于白板。

## 大图分段落笔

图一大就一段一段加，不要一次吐完：先主线，再分区，再区内细节。每段落下笔前想清楚它和已有元素怎么接，接完的 arrow 要回到上一段。

## 画完必须验（没有渲染器，就核坐标）

1. `notes_board action: "read"` 把板子读回来。
2. 对着同构检验过一遍：结构还讲得清吗？
3. 逐项核：文字有没有被容器裁掉、元素是否重叠、箭头是否落在目标上而不是空白、相邻元素间距是否一致、是否出现过大的空洞或挤成一团。
4. 有问题就 `replace: true` 重画，不要在原图上打补丁。通常要 2~4 轮。

## 自检清单

- [ ] 同构检验过了吗？删掉字还看得出结构吗？
- [ ] 每个主要概念用了不同模式吗？有没有一排等大方框？
- [ ] 关系都有 arrow / line 吗？
- [ ] 装进框里的 text 少于 30% 吗？
- [ ] 技术图有证据块、真实名字吗？
- [ ] 颜色都来自色板，语义一致吗？
- [ ] `roughness 0`、`opacity 100`、`fontFamily 3` 吗？
- [ ] 读回来核过坐标，没有裁切、重叠、悬空箭头吗？
