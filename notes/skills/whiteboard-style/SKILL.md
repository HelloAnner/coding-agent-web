# 白板风格

一句话：**少、准、留白**。画的不是功能清单，是一张能讲清核心关系的草图。

判断标准不是「信息全不全」，而是「别人看 20 秒能不能说出这张图在讲什么」。

## 立场：白板要论证，不要罗列

- 画之前先用**一句话**说出这张图的主张，比如「notes 是生产的入口，coding 是执行的手」。
- **同构检验**：把字全去掉，光看结构还能读出关系吗？读不出就重画，不是加字。
- **每个主角用不同构图**（见下面的模式表）。一排大小相同的框 + 箭头，是没有主张的图。
- **关系必须画出来**。两个元素挨着不算有关系，得有 arrow 或 line。
- 用**真实的名字**：真事件名、真接口、真字段，不用 `Input` / `Process` / `Output` 这种占位词。技术内容先查清楚再画。
- 细节、异常分支、字段表都不进白板，那是笔记的事。

## 能画的，不要写

先问一句：这句话能不能变成一个结构？能，就画，不要写字。

| 文字里的内容 | 画成什么 |
| --- | --- |
| A 导致 B、A 决定 B | 两个节点 + arrow，短语标在箭头上 |
| 为什么选 A 不选 B | 左右并排两组，中间留白，各一个短标签 |
| 先 1 再 2 再 3 | 横线 + 小圆点 + 短标签 |
| 包含、分层 | 容器 + line 分格 + 裸 text |
| 多个汇成一处、一个分出多条 | 收拢 / 放射的 arrow |
| 数量、占比 | 节点大小和间距的对比，不写「大 / 小」 |

字的预算（硬限制）：

- 一条 text 最多 **两行、24 个汉字**。超过就不是标签，是段落：要么改画，要么删。
- 一个区域最多 **6 条 text**：2~4 条旁注 + 箭头短语。多区域的板按区域算。
- 把全图的字连起来读一遍。读起来像一篇短文，说明你在把笔记搬到白板上，继续删。

## 先判深度

| 概念图（多数情况） | 技术图（少数情况） |
| --- | --- |
| 讲一个思路、取舍、边界 | 讲一个真实系统怎么跑 |
| 3~6 个节点，抽象词 | 5~8 个节点，真实名字 |
| 旁注写「为什么」 | 旁注写约束和坑 |
| 一句话片段可以贴，最多 3 行 | 可以贴一小段真实数据/调用，最多 3 行 |

两种都不画全貌：一个区域一个主张，一整块板也只讲一个主题。

## 构图模式（按「这个概念在做什么」选）

| 概念在做什么 | 怎么画 | 用的形状 |
| --- | --- | --- |
| 一个东西分出多条出路 | 从中心放射出去 | ellipse 中心 + 多条 arrow |
| 多条汇成一个结果 | 箭头收拢到一点 | 多条 arrow → 一个 ellipse |
| 有层级、包含关系 | 树干 + 分支，标签裸写 | line 做树干，text 做标签 |
| 有先后顺序 | 横线 + 小圆点 + 旁边文字 | line + 12px ellipse + text |
| 会循环、会回头 | 首尾接上，箭头回起点 | arrow 回环 |
| 模糊的状态、上下文 | 两个椭圆叠一点 | ellipse 重叠 |
| 输入被处理成输出 | 前 → 中 → 后，左边乱右边齐 | 3 段 + 2 条 arrow |
| 两件事对比 | 左右平行，用留白隔开 | 两组并排，中间不连线 |
| 分阶段、有断点 | 中间留一段空白，不画东西 | 只靠留白 |

规则：一个区域最多用 2 种模式；主角用不同的模式。

## 用词

读图的人没看过对话，他只看得见板上的字。

- 节点名要能念出来（「冻结基线」不是 `frozen_id`）；必须用代号，就紧挨着补一句 13~14px 的人话解释。
- 箭头短语用动词：「决定」「拦不住」「回滚到」「先于」「不写入」；不写「关联」「依赖关系」这种名词化的空话。
- 黑话（不变量、基线、幂等、兜底）第一次出现就随口解释一句：只说是什么、管什么，不讲原理。
- 解释也是 text，算在 6 条里；放不下就把解释合并成一句，不要堆成段落。

## 板内分区

一张板讲一个主题的几面：现状 / 方案 / 顺序 / 坑。

- 每个区域 3~8 个节点，左上角一条 16~18px 标题 text；区域之间留 ≥240 空白，或一条竖 line 分隔。
- 区域内部照常用上面的构图模式连箭；跨区域只在真有因果、调用、先后时拉 arrow，不为了连而连。
- 盖章测试：盖掉别的区域，这一块还讲得通；盖掉后只剩一堆孤立的框，重排坐标。
- 视线顺序是标题 → 区域内的结构 → 箭头去下一个区域；眼睛来回跳就重排。

## 形状的语义（不要混用）

| 形状 | 只用来表示 | 例子 |
| --- | --- | --- |
| `ellipse` | 概念、角色、外部系统；12px 时是时间轴上的点 | `global config`、`kms/飞书文档`、`自动化` |
| `rectangle` | 容器、模块、界面；要分格就加 `line` 分隔 | `coding`（三格）、`notes`（两列） |
| `arrow` | 唯一表示流向 / 因果 / 调用的形状 | `pi + notes skill` |
| `line` | 分隔线、树干、没有方向的连接 | 容器内的分格线 |
| `text` | 形状上方的说明、箭头标签、孤立旁注 | `保存到全局的配置文件` |

## 容器纪律

**默认裸文字。** 加框以前先问：这句话去掉框还能读吗？能就删框。

- 只有「一个真实存在的东西」（系统、模块、界面）才配 rectangle。
- 一句解释、一个标签、一句结论，一律裸 text。
- 全图装进框里的文字别超过 30%。超过说明你在画表格，不是在画图。

## 尺寸与留白

| 东西 | 值 |
| --- | --- |
| ellipse 概念 | 160×90，label 居中，16~18px |
| rectangle 容器 | 220×(90~200)，label 16~18px |
| 形状上方的说明 | 13~14px，落在形状上方 24~36px |
| 箭头 / 连线长度 | 120~240，横平竖直，倾斜 ≤15° |
| 节点间距 | ≥160（横向）、≥140（纵向） |
| 旁注 | 13~14px，行距 1.6，放在图的空白区 |

字号就是层级：主角 18~20，普通节点 16，说明和旁注 13~14。不要再加别的字号。

**留白即权重**：最重要的那个东西，周围空得最多。一片空区比再画三个框更有说服力。

## 画法顺序

1. 把对话读成一份**事实清单**：一条一行，`A —— 短语 —— B`，只取定稿的事实（系统怎么跑、定了什么），不取讨论过程和备选。用户反复追问、拍板的那几条排最前面；量少时删细节，不删事实。
2. 写下一句话主张。写不出来就先别画。
3. 定 **2~3 个主角**，横排或竖排，间距 240。主角是「谁和谁有关系」，不是每一步操作。
4. 给每个主角选一种构图模式，再用 arrow / line 把它们连起来，关系用一句短语标在箭头上（`automatic`、`指导代码生成`）。
5. 需要解释的地方，从概念拉一条 arrow 或 line 到一句 `text`，**不要再画一个框**。
6. 补 2~4 条旁注：为什么这样、边界在哪、结论是什么。旁注写人话。
7. 先想一遍视线路径（左→右 / 上→下 / 放射），确认眼睛不会来回跳。
8. 对着事实清单逐条打勾：每条都要有两个节点 + 一条 arrow。只剩节点没箭头，就是事实丢了，回去补。
9. 自检：**删掉任意一个节点，图还讲得通吗？** 讲得通就删掉它。

## 画完自检（没有渲染器，只能核坐标）

- 对着事实清单把每一条念一遍：两个节点都在、箭头在两个之间、短语在箭头上。少一条就补，不要用「图上已经能看出来」糊弄。
- 板上有没有还在讨论、没定、试过没走通的东西？有就删。

- 估字宽：中文每字 ≈ 字号宽，英文 ≈ 0.6 字号。一行放不下就 `\n`，不要靠画布自适应。
- 箭头起终点落在**边界**上，不是圆心：ellipse 从 `(x+160, y+45)` 出发，到 `(x, y+45)`。
- 箭头不要穿过别的形状；两条箭头不要贴在一起走。
- 间距要一致：同一行的节点 y 相同，竖排的 x 相同。
- 一边挤、一边大片空 = 还没画完，调坐标，别加内容。
- 看一遍：有没有箭头指向空处、有没有标签离它说的东西太远。这两条是返工最多的。
- 把每条 text 念一遍：能画成形状的都改画；剩下必须是「不写就看不懂」的那几句。

## 字体

字体来自笔记设置（设置 → 白板）。想要截图那种手写感，字体选 `Excalifont`（或 `Virgil`）；默认 `Cascadia` 等宽也成立，前提是**字少**。
