# 写笔记

目标是让别人（和三个月后的自己）能直接读懂，不是把聊天记录抄一遍。

## 结构

1. 第一行是一句话结论或目的。
2. 需要背景才写背景，最多两段。
3. 主体按「问题 → 做法 → 结果」或「决定 → 原因 → 影响」组织。
4. 结尾只留在真的有人要做的事；没有就不写。

## 写法

- 标题层级从 `##` 开始：文件名就是标题，不要再写一个 `#`。
- 每段 3 行以内，一段只说一件事。
- 列表用于并列项；有先后关系用编号列表。
- 代码、路径、命令一律用反引号，能跑的命令用 ``` 代码块并标语言。
- 数字给出来源或口径，例如「P95 320ms（近 7 天线上）」。
- 不确定的内容标「待确认」，不要编。

## 例子

```markdown
把 notes 面板的 agent 从占位改成可用的多轮会话，本周只做核心链路。

## 做了什么

- 接 pi 的 AgentSession，工具只给 `read`、`ls`、`notes_write`、`notes_board`
- 会话存在内存里，重启清空；文件落盘才是长期记忆
- 白板由形状列表生成 scene，不让模型手写 JSON

## 决定

白板字体跟着笔记设置走，不按每个元素单独配。原因：改一次全局生效，比逐块调整省事。

## 待确认

- 会话要不要落盘到 `.notes/agent/`，还是保持内存
```

## 边界

- 不写没发生的决定，不补用户没说的事实。
- 不要为了凑结构写空的「背景」「风险」小节。
